# JavaScript promises at browser, effect, and terminal boundaries

Research snapshot: 2026-11-14. This study follows actual Gleam declarations, JavaScript implementations, examples, tests, and dependency manifests in four repositories. Links pin the inspected commits; the version printed in `gleam.toml` is not a claim that HEAD equals that release tag. **Observation** describes the source; **inference** identifies a consequence or risk; **recommendation** is advice drawn from it.

## Lustre: an effect owns initiation; messages own completion

**Observation.** `Effect(message)` is opaque and stores lists of callback closures for synchronous, before-paint, and after-paint work. `effect.from` accepts `fn(dispatch) -> Nil`; constructing it records the callback rather than running its body. A promise-returning API can therefore be started inside that callback and later dispatch a typed message. The effect callback itself does not return a promise for Lustre to await. This is an architectural boundary, not a language-level proof that `update` cannot perform side effects. [Representation](https://github.com/lustre-labs/lustre/blob/c2f25c601dc7abfe35e8e58acfd4fb5bcdbb6e81/src/lustre/effect.gleam#L84-L110), [constructor](https://github.com/lustre-labs/lustre/blob/c2f25c601dc7abfe35e8e58acfd4fb5bcdbb6e81/src/lustre/effect.gleam#L123-L162), [runtime invocation](https://github.com/lustre-labs/lustre/blob/c2f25c601dc7abfe35e8e58acfd4fb5bcdbb6e81/src/lustre/runtime/client/runtime.ffi.mjs#L258-L301).

**Observation.** Immediate dispatches during effect execution enter a FIFO message queue. The runtime drains these update/effect cycles before completing that effect pass. Promise callbacks that run later dispatch through the same runtime but are not members of a promise-completion queue managed by Lustre. Normal dispatch schedules a render and handles effects; the runtime invokes callbacks without inspecting their return values. [Dispatch](https://github.com/lustre-labs/lustre/blob/c2f25c601dc7abfe35e8e58acfd4fb5bcdbb6e81/src/lustre/runtime/client/runtime.ffi.mjs#L110-L122), [actions and queue processing](https://github.com/lustre-labs/lustre/blob/c2f25c601dc7abfe35e8e58acfd4fb5bcdbb6e81/src/lustre/runtime/client/runtime.ffi.mjs#L228-L301).

**Observation.** Before-paint work runs after DOM reconciliation, through an explicitly queued microtask. The comment explains that this lets already queued microtasks, including promise callbacks from synchronous effects, run first. After-paint work uses `requestAnimationFrame`. These are scheduling phases, not guarantees that an arbitrary network promise will settle before painting. Both paint-related effect kinds are documented as ignored by server components. [Browser scheduling](https://github.com/lustre-labs/lustre/blob/c2f25c601dc7abfe35e8e58acfd4fb5bcdbb6e81/src/lustre/runtime/client/runtime.ffi.mjs#L313-L344), [phase contracts](https://github.com/lustre-labs/lustre/blob/c2f25c601dc7abfe35e8e58acfd4fb5bcdbb6e81/src/lustre/effect.gleam#L164-L218).

**Recommendation.** Create the asynchronous operation inside the effect callback so constructing the effect does not initiate it early. Start dependent work in one chained operation, or dispatch a completion message that starts the next effect. Do not infer sequencing from `effect.batch`: its public contract explicitly declines ordering guarantees and recommends those two approaches. Keep DOM measurements in before-paint work, and reserve synchronous dispatch there for bounded adjustments; the docs warn that repeated rerenders can prevent painting. [Batch contract](https://github.com/lustre-labs/lustre/blob/c2f25c601dc7abfe35e8e58acfd4fb5bcdbb6e81/src/lustre/effect.gleam#L307-L325), [render-loop warning](https://github.com/lustre-labs/lustre/blob/c2f25c601dc7abfe35e8e58acfd4fb5bcdbb6e81/src/lustre/effect.gleam#L173-L183).

Native promise use supplies useful counterexamples:

- Stylesheet adoption creates promises for load/error events, waits with `Promise.allSettled`, then checks whether the host was disconnected while waiting. **Lesson:** tolerate individual failures when the operation permits it, and recheck lifecycle state after suspension. [Implementation](https://github.com/lustre-labs/lustre/blob/c2f25c601dc7abfe35e8e58acfd4fb5bcdbb6e81/src/lustre/runtime/client/runtime.ffi.mjs#L364-L415).
- The polling transport chains fetch → JSON → message callback and logs rejection. Its interval starts new fetches without serializing them; **inference:** a slow request can overlap a later interval and completion order need not equal start order. No live transport race was reproduced here. [Transport](https://github.com/lustre-labs/lustre/blob/c2f25c601dc7abfe35e8e58acfd4fb5bcdbb6e81/src/lustre/runtime/client/server_component.ffi.mjs#L774-L808).
- The autoplay special case calls `node.play()` inside synchronous `try/catch`, ignoring the returned promise. **Inference:** this catches a synchronous throw, not a later rejection from that promise. Contrast Plinth's awaited audio wrapper below. [Autoplay handler](https://github.com/lustre-labs/lustre/blob/c2f25c601dc7abfe35e8e58acfd4fb5bcdbb6e81/src/lustre/vdom/reconciler.ffi.mjs#L694-L701).

The separate server example uses `Promise(Response(ReadableStream))` for handlers and `Promise(smol.Step(...))` for websocket updates, while delegating the actual asynchronous operations to Smol. This is typed promise use at a server-adapter boundary, not a new Lustre effect API. [HTTP handlers](https://github.com/lustre-labs/lustre/blob/c2f25c601dc7abfe35e8e58acfd4fb5bcdbb6e81/examples/06-server-components/01-basic-setup-javascript/src/app.gleam#L82-L124), [websocket update](https://github.com/lustre-labs/lustre/blob/c2f25c601dc7abfe35e8e58acfd4fb5bcdbb6e81/examples/06-server-components/01-basic-setup-javascript/src/app.gleam#L140-L167).

## Plinth: normalize failures where the binding can understand them

**Observation.** Plinth deliberately exposes low-level platform APIs. Its useful async boundary pattern is `Promise(Result(value, String))`, with `try { await native_operation() } catch { return Error(String(error)) }` in FFI. Audio, clipboard, file-system, cryptography, and dynamic imports contain this pattern; serial operations instead commonly return `Error(Nil)`. The `await` is important: returning a native promise directly from the `try` would not catch its later rejection. [Stated design](https://github.com/CrowdHailer/plinth/blob/ba246f26ff05ef933a5e1664def8d59ffbde317d/README.md#L6-L15), [audio](https://github.com/CrowdHailer/plinth/blob/ba246f26ff05ef933a5e1664def8d59ffbde317d/src/audio_ffi.mjs#L7-L14), [clipboard](https://github.com/CrowdHailer/plinth/blob/ba246f26ff05ef933a5e1664def8d59ffbde317d/src/clipboard_ffi.mjs#L1-L17), [file system](https://github.com/CrowdHailer/plinth/blob/ba246f26ff05ef933a5e1664def8d59ffbde317d/src/file_system_ffi.mjs#L72-L102), [crypto](https://github.com/CrowdHailer/plinth/blob/ba246f26ff05ef933a5e1664def8d59ffbde317d/src/plinth_browser_crypto_subtle_ffi.mjs#L91-L107), [serial](https://github.com/CrowdHailer/plinth/blob/ba246f26ff05ef933a5e1664def8d59ffbde317d/src/serial_ffi.mjs#L3-L20), [import](https://github.com/CrowdHailer/plinth/blob/ba246f26ff05ef933a5e1664def8d59ffbde317d/src/window_ffi.mjs#L154-L160).

This policy is not uniform:

| Surface | Observed semantics |
|---|---|
| Blob/file text and bytes | Expose `Promise(String)`/`Promise(BitArray)` and pass through or await native operations without converting rejection. [Blob types](https://github.com/CrowdHailer/plinth/blob/ba246f26ff05ef933a5e1664def8d59ffbde317d/src/plinth/browser/blob.gleam#L1-L12), [blob FFI](https://github.com/CrowdHailer/plinth/blob/ba246f26ff05ef933a5e1664def8d59ffbde317d/src/blob_ffi.mjs#L9-L15), [file FFI](https://github.com/CrowdHailer/plinth/blob/ba246f26ff05ef933a5e1664def8d59ffbde317d/src/file_ffi.mjs#L11-L17). |
| Compression/decompression | Return promised bytes; constructing streams and reading output occur inside async functions without catch. [Compression](https://github.com/CrowdHailer/plinth/blob/ba246f26ff05ef933a5e1664def8d59ffbde317d/src/compression_stream_ffi.mjs#L1-L11), [decompression](https://github.com/CrowdHailer/plinth/blob/ba246f26ff05ef933a5e1664def8d59ffbde317d/src/decompression_stream_ffi.mjs#L1-L11). |
| Service-worker `client_get` | `Error(Nil)` represents missing client, but native lookup rejection is not caught. A `Result` payload does not by itself prove rejection normalization. [Type](https://github.com/CrowdHailer/plinth/blob/ba246f26ff05ef933a5e1664def8d59ffbde317d/src/plinth/browser/service_worker.gleam#L79-L86), [FFI](https://github.com/CrowdHailer/plinth/blob/ba246f26ff05ef933a5e1664def8d59ffbde317d/src/service_worker_ffi.mjs#L77-L87). |
| Service-worker `do_claim` | The returned promise completes after registering an activate listener; the later claim operation is owned by `event.waitUntil`, not chained to that returned promise. Awaiting the wrapper does not mean “claim completed.” [Declaration](https://github.com/CrowdHailer/plinth/blob/ba246f26ff05ef933a5e1664def8d59ffbde317d/src/plinth/browser/service_worker.gleam#L38-L47), [implementation](https://github.com/CrowdHailer/plinth/blob/ba246f26ff05ef933a5e1664def8d59ffbde317d/src/service_worker_ffi.mjs#L27-L35). |
| Node readline | `question` forwards the native return. `close` is declared `Promise(String)` but merely returns `rl.close()`. A direct probe of this unchanged FFI with a real readline interface returned `undefined` on Node 26.13.1: a confirmed declaration/implementation mismatch on that runtime. [Types](https://github.com/CrowdHailer/plinth/blob/ba246f26ff05ef933a5e1664def8d59ffbde317d/src/plinth/node/readlines.gleam#L12-L16), [FFI](https://github.com/CrowdHailer/plinth/blob/ba246f26ff05ef933a5e1664def8d59ffbde317d/src/plinth_node_readlines_ffi.mjs#L8-L14). |

**Observation.** The Gleam callback adapters are worth studying. Geolocation's `current_position` creates one promise, decodes successful callback data, and resolves either decoded `Ok` or an error string. IndexedDB's `opendb` handles both synchronous failure to initiate opening and later success/error callbacks, resolving typed results in either case. Neither requires a rejection callback in the Gleam constructor. Storage's `estimate` then illustrates a small `promise.map_try` transformation from a successful tuple into the domain `Estimate` record. [Geolocation](https://github.com/CrowdHailer/plinth/blob/ba246f26ff05ef933a5e1664def8d59ffbde317d/src/plinth/browser/geolocation.gleam#L55-L74), [database open](https://github.com/CrowdHailer/plinth/blob/ba246f26ff05ef933a5e1664def8d59ffbde317d/src/plinth/browser/indexeddb/factory.gleam#L13-L44), [storage mapping](https://github.com/CrowdHailer/plinth/blob/ba246f26ff05ef933a5e1664def8d59ffbde317d/src/plinth/browser/storage.gleam#L9-L19).

**Counterexample, confirmed by isolated probe.** The separate IndexedDB object-store helper constructs `new Promise(function(resolve) { ... })`, but its error event handler calls `reject(event)` without defining `reject`. A later error event therefore throws `ReferenceError` and leaves that promise pending; the surrounding async function's `try/catch` does not catch the later event-handler throw. Both `get_all` and `put` await this helper. A synchronous `getAll()` throw, by contrast, is converted to `Error`. **Recommendation:** test callback failure settlement, not only successful resolution or synchronous exceptions. [Callers and broken bridge](https://github.com/CrowdHailer/plinth/blob/ba246f26ff05ef933a5e1664def8d59ffbde317d/src/plinth_indexeddb_ffi.mjs#L77-L109).

## Lustre UI: hide JavaScript mechanics behind a narrow callback

**Observation.** Accordion animation returns `Nil` to Gleam and reports measured width/height through a callback that dispatches `PanelMeasuredDimensions`. Its FFI dispatches pixel dimensions immediately; on expansion it waits until an animation frame, joins animation-finished promises, then dispatches `auto` dimensions. Collapse schedules zero dimensions for the next frame. Promises are an implementation mechanism; the domain event is the interface. [Gleam boundary](https://github.com/lustre-labs/ui/blob/a7f2deab9fbde907397a61f75fb211910831c47d/src/lustre/ui/accordion/panel.gleam#L190-L218), [animation FFI](https://github.com/lustre-labs/ui/blob/a7f2deab9fbde907397a61f75fb211910831c47d/src/lustre/ui/accordion/panel.ffi.mjs#L3-L23).

Tooltip positioning likewise uses a callback-based `Nil` FFI declaration, starts it in a before-paint effect, and translates coordinates into `DomCalculatedPosition`. The FFI calls vendored Floating UI's asynchronous `computePosition(...).then(...)`. Tooltip hiding waits for all current animation promises. [Gleam effects](https://github.com/lustre-labs/ui/blob/a7f2deab9fbde907397a61f75fb211910831c47d/src/lustre/ui/tooltip/popover.gleam#L383-L440), [tooltip FFI](https://github.com/lustre-labs/ui/blob/a7f2deab9fbde907397a61f75fb211910831c47d/src/lustre/ui/tooltip/popover.ffi.mjs#L1-L60), [vendored async implementation](https://github.com/lustre-labs/ui/blob/a7f2deab9fbde907397a61f75fb211910831c47d/src/lustre_ui/vendor/floating_ui/core.ffi.mjs#L77-L120).

**Inferences, not reproduced UI bugs.** Accordion completion and tooltip hiding attach empty catches, so any rejection in those chains suppresses the completion action and is discarded. Tooltip coordinate calculation has only a fulfillment handler and no rejection handler. None of these callbacks carries an operation ID or checks whether newer open/close/position work superseded it; stale completion is therefore a risk to assess when adapting the pattern. **Recommendation:** keep the narrow domain callback, but choose an explicit error policy and guard stale or disconnected completion when it matters. The source does not establish that silently ignoring every animation failure is appropriate in another application. [Accordion chain](https://github.com/lustre-labs/ui/blob/a7f2deab9fbde907397a61f75fb211910831c47d/src/lustre/ui/accordion/panel.ffi.mjs#L8-L21), [tooltip chains](https://github.com/lustre-labs/ui/blob/a7f2deab9fbde907397a61f75fb211910831c47d/src/lustre/ui/tooltip/popover.ffi.mjs#L45-L60).

## Etch: promise completion, optional events, and typed failure are separate layers

**Observation.** `poll` and `read` expose `Promise(Option(Result(Event, EventError)))`: asynchronous availability outside, timeout/absence next, parsed event versus parse failure inside. The adapter initializes its input server once, starts a background recursive promise loop, and returns `Nil` without retaining that loop's promise. Each input chunk is parsed and pushed into the FFI queue. [API and initialization](https://github.com/bananaofhappiness/etch/blob/edbd39dd1adbfc8916ef0df03c5df283f2599f95/etch_javascript/src/etch/javascript/input.gleam#L12-L70).

The JavaScript implementation has separate FIFO arrays for available events and waiting resolvers. `push` satisfies one waiter or buffers an event. `poll` removes its waiter on timeout and clears its timer on delivery; `read` waits without a timer. There is no cancellation or queue bound in these functions. `get_chars` handles stdin data/end/error and removes listeners, but rejects on stream error; the background Gleam loop attaches no rescue. Thus typed event parse errors and native stream rejection are different paths. [Input cleanup/rejection](https://github.com/bananaofhappiness/etch/blob/edbd39dd1adbfc8916ef0df03c5df283f2599f95/etch_javascript/src/etch/javascript/input_ffi.mjs#L19-L59), [queues](https://github.com/bananaofhappiness/etch/blob/edbd39dd1adbfc8916ef0df03c5df283f2599f95/etch_javascript/src/etch/javascript/input_ffi.mjs#L62-L102).

**Counterexample, confirmed by isolated probe.** `push` supplies `Some(event)` to a waiter; the pending `poll` resolver wraps that value in another `Some`. Consequently a queued poll and a waiting read produce `Some(event)`, while a poll fulfilled during its wait produces `Some(Some(event))`, violating the Gleam signature. Timeout still produces `None`. **Recommendation:** test already-buffered, live-delivery, and timeout paths against the same public type. [Wrapping sites](https://github.com/bananaofhappiness/etch/blob/edbd39dd1adbfc8916ef0df03c5df283f2599f95/etch_javascript/src/etch/javascript/input_ffi.mjs#L62-L102).

**Observation.** The simple hello-world loop awaits `input.read`, handles synchronously, then returns the recursive loop's promise. Snake sequences a sleep, poll, state update, and next iteration; its end screens use `promise.tap` after a delay to perform a terminal exit. These demonstrate continuation-based sequencing without blocking JavaScript's event loop. [Read loop](https://github.com/bananaofhappiness/etch/blob/edbd39dd1adbfc8916ef0df03c5df283f2599f95/examples_javascript/src/hello_world.gleam#L29-L55), [game loop](https://github.com/bananaofhappiness/etch/blob/edbd39dd1adbfc8916ef0df03c5df283f2599f95/examples_javascript/src/snake.gleam#L123-L141), [delayed exits](https://github.com/bananaofhappiness/etch/blob/edbd39dd1adbfc8916ef0df03c5df283f2599f95/examples_javascript/src/snake.gleam#L407-L417).

**Counterexample.** The larger events example calls promise-returning `handle_input(event)` without chaining it before starting another read. Several branches create a promise with `use _ <- promise.new()` and never call the resolver; their synchronous side effects can run while the resulting promise remains pending. Calling `promise.resolve(pos)` and then discarding it does not settle those other promises. **Recommendation:** return/await asynchronous handlers to preserve sequencing, and return an already-resolved value for completed synchronous work instead of manufacturing an unresolved promise. [Loop and pending branch](https://github.com/bananaofhappiness/etch/blob/edbd39dd1adbfc8916ef0df03c5df283f2599f95/examples_javascript/src/events.gleam#L40-L69), [query branches](https://github.com/bananaofhappiness/etch/blob/edbd39dd1adbfc8916ef0df03c5df283f2599f95/examples_javascript/src/events.gleam#L112-L158), [discarded branch results](https://github.com/bananaofhappiness/etch/blob/edbd39dd1adbfc8916ef0df03c5df283f2599f95/examples_javascript/src/events.gleam#L174-L184).

## Validation and limits

- Inspected Plinth's async compression round-trip and HMAC tests: they return promise chains and assert successful results. No IndexedDB error-event settlement test was found in the searched test tree. [Compression tests](https://github.com/CrowdHailer/plinth/blob/ba246f26ff05ef933a5e1664def8d59ffbde317d/test/gunzip_test.gleam#L1-L22), [HMAC tests](https://github.com/CrowdHailer/plinth/blob/ba246f26ff05ef933a5e1664def8d59ffbde317d/test/plinth/browser/crypto/subtle_test.gleam#L18-L49).
- Inspected Lustre's integration harness: it awaits test callbacks, unregisters Happy DOM in `finally`, and waits two animation frames for its frame helper. This is test orchestration, not evidence that arbitrary application promises settle within two frames. No focused promise/effect-ordering test was found by the scheduling search. [Harness cleanup](https://github.com/lustre-labs/lustre/blob/c2f25c601dc7abfe35e8e58acfd4fb5bcdbb6e81/test/integration/client_test.ffi.mjs#L1-L18), [frame helper](https://github.com/lustre-labs/lustre/blob/c2f25c601dc7abfe35e8e58acfd4fb5bcdbb6e81/test/integration/client_test.ffi.mjs#L151-L157).
- Etch's nested JavaScript tests cover raw-mode and terminal-size operations, not the promise queue. UI had no tracked test/spec files in the inspected inventory. [Etch adapter tests](https://github.com/bananaofhappiness/etch/blob/edbd39dd1adbfc8916ef0df03c5df283f2599f95/etch_javascript/test/etch_javascript_test.gleam#L1-L45).
- Ran isolated Node.js v26.13.1 probes against the actual Etch queue and Plinth IndexedDB function bodies, removing module imports and supplying minimal constructor stubs. The probes confirmed the queue and IndexedDB counterexamples, including the synchronous-versus-event-error distinction. A separate probe imported the unchanged readline FFI with a real Node readline interface and confirmed its non-promise return. These checks did not compile Gleam, exercise generated representations, emulate a browser/terminal, or run the repositories' full suites. The temporary harness was `/tmp/gleam-promises-browser-probes.mjs`.
- Native `Promise(a)` FFI boundaries and Gleam combinator implementations must be inspected separately. The adapter locks above do not justify projecting newer `gleam_javascript` nested-promise behavior onto older releases. No claim here depends on that behavior. Live animation races, browser permission failures, readline behavior on other runtimes, and complete package build compatibility remain unverified.
